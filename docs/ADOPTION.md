# Adoption and Design Partners

Open Growth Loop is early. The project needs real maintainer feedback more than vanity metrics.

## Run a 20-Minute Field Test

Use a public repository you maintain or have permission to inspect:

```bash
pip install git+https://github.com/R3ijar/open-growth-loop
ogl steward --workspace path/to/repository
```

Review `outbox/steward/latest-steward.md`, then share one of these outcomes in a GitHub issue:

- the recommended action was useful and why;
- the recommendation missed more important maintainer work;
- installation or report language was confusing;
- a repository shape or ecosystem was not handled correctly.

Redact private repository data before sharing reports.

Use the [structured maintainer field-test form](https://github.com/R3ijar/open-growth-loop/issues/new?template=design_partner.yml). No call or continuing commitment is required. If you do not know other maintainers, use the [low-contact outreach playbook](OUTREACH.md) rather than sending bulk messages.

## Evidence We Record

Public adoption claims must link to evidence. Acceptable evidence includes a public repository using the Action, a public issue from an independent maintainer, an external pull request, or public package-download data. Stars alone do not prove use.

## Near-Term Targets

- Five independent maintainers complete the field test.
- Ten public repositories run the audit or steward workflow.
- Two external issues lead to shipped fixes.
- One external contributor completes a pull request.
- The first stable release is published only after the install path is verified from a clean environment.

These are project targets, not current achievements.
